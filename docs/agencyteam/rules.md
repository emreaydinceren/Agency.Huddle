# Rules that are not visible in the code

**Binding.** Read this in full before changing anything in `src/Huddle.App`.
Each row cost real time to discover, and several were found by running the app
rather than by testing it — the compiler will not catch any of them.

Protocol, ACP and wire gotchas live in [Traps](traps.md); read that too if you
are touching `Huddle.Acp`, `Huddle.Contracts`, or the model-config path. Back to the
hub: [AgencyTeam.md](../AgencyTeam.md).

These cost real time to discover. Several were found by running the app, not by
testing it. This table is binding.

| Rule | Why |
| --- | --- |
| **Never use `UseAdvancedExtensions()` in the markdown pipeline.** | It enables generic attributes, so `# Hi {onclick="alert(1)"}` renders a live event handler. `DisableHtml()` does not stop it. Agent text is model output, so this is reachable. |
| **A Name may contain single interior spaces; a Mention is resolved against the Members, not by a pattern.** | `@Emily Lee` and `@Emily` followed by the word "Lee" are the same characters, so no regex can tell them apart. `MentionParser` matches Member Names against the text, longest first, and the Room's membership decides where a Name ends. Anything that parses a Name — `/invite`, a new command — must resolve it the same way or it will silently truncate at the first space. |
| **Leading, trailing and doubled spaces in a Name are rejected.** | Mention resolution matches a Name character by character against message text, so `Emily  Lee` beside `Emily Lee` is a distinction no reader can see. `NameRules` anchors with `\A`/`\z` rather than `^`/`$` for a related reason: .NET's `$` matches before a trailing newline, so `^[a-z]+$` would accept `"coo\n"`. This rule was *also* justified by a Name being a Persona's filename; identity moved to frontmatter and that half retired, but the rule did not — `PersonaStore.Add` still builds `{Name}.md`, and `NameRules` is still the path-traversal guard there. |
| **A Persona's identity is its frontmatter, never its filename or its folder.** | `name`, `title` and `alias` are required; `teams` is optional. `PersonaIndex` keys everything on the frontmatter `name` — the `persona_models` and `persona_efforts` rows, the work dir, the `hello` identity. A file is free to be named anything and to live in any sub-folder, and **moving it between Team sub-folders is a complete no-op**. That is the whole point of Team membership being a field: sub-folders are the human's filing system and the code must never read meaning into them. |
| **A malformed Persona file is reported, never swallowed.** | A missing required field, or a Name or Alias colliding with another file's, makes the file a `RejectedPersonaFile` carrying its path and reason, listed on `/teammates`. A file that fails to load must be visible — the alternative is a Teammate that silently does not exist and a human who cannot tell why. |
| **A duplicate Name or Alias rejects *every* colliding file, not all but one.** | Picking a winner by enumeration order means editing the loser does nothing at all, with no feedback anywhere. Comparison is case-insensitive, matching `persona_models`' `COLLATE NOCASE` and `MentionParser`'s `OrdinalIgnoreCase` — so `Jarvis` and `jarvis` collide rather than becoming two runners sharing one Model row. |
| **`Teams: a, b` is split at the consumer and never in `PersonaFrontmatter`.** | The generic parser deliberately refuses to read a comma-separated scalar as a list, because real frontmatter contains `role: 'Router, triage, and cross-workstation continuity'` and splitting that would shred a sentence into fields. Only the `teams` key is ever split, after the generic parse. The cost, accepted: a Team name can never contain a comma. |
| **An Alias is accepted anywhere a Name is.** | `mcp__team__list_agents` advertises each Teammate's Alias in its job description, so `@jar`, `/invite @jar`, `mcp__team__invite_agent` and `mcp__team__create_room` must all take it. A tool that rejects a handle the model was just told about costs a turn and teaches the model not to trust the catalog. |
| **Sample agents must strip `@` from quoted text.** | Two agents that quote what they received answer each other forever. A failing test recorded 4299 messages in two seconds. |
| **`Team:DataDir` must not be `data`.** | Windows paths are case-insensitive, so it collides with the `src/Huddle.App/Data/` source folder, and the ignore rule then hides the storage layer from git. |
| **Collection options need no initialiser.** | `ConfigurationBinder` *appends* to a pre-populated collection instead of replacing it, silently doubling the value. Declare nullable, default inside the consumer. |
| **Both test fixtures must set `Team:DemoAgent:Enabled=false`.** | The demo agents use the names `echo` and `alpha`, which collide with the names the pipe tests register, and one test asserts the sidebar is empty. |
| **Create the next pipe server instance before any I/O on the accepted one.** | Otherwise the next client fails with "all pipe instances are busy". |
| **Every component subscribing to `RoomEvents` must unsubscribe in `Dispose`.** | The hub is a singleton; a leaked component throws on disconnect and never dies. |
| **An Agent never receives its own Message.** | Structural, in `AgentGateway.DeliverAsync`. It is what stops naive clients echo-looping. |
| **ACP is off by default and spends real money.** | `Team:Acp:Enabled` defaults to `false`, and both test fixtures pin it `false` explicitly. Turning it on starts real `node` adapter processes that bill the user's Claude subscription. |
| **App Tool names must be spelled with their Adapter's prefix in the system prompt.** | Naming a tool imprecisely makes the model report that no such tool exists. The prefix is built in code from the **Adapter Profile** and the tool-server name, never typed into a hook template. For `claude-agent-acp` it is `mcp__team__`; for `agency-acp` it is empty, because `McpClientPool` surfaces a remote tool under the server's own name unmodified. `PromptGoldenTests` pins **both** forms — `systemPrompt.txt` and `systemPrompt.unprefixed.txt` — and the prefixed golden is byte-identical to before Adapters became selectable, which is what proves a stock install is unchanged. It holds inside `get_help`'s own output too: that text is the only place many Agents will read a tool's name. |
| **A Turn's Room label carries the Room's id, and it is the only place an Agent can learn one.** | `mcp__team__post_message` and `mcp__team__invite_agent` both take a room id. Nothing else in a Turn carries one, so shortening the label back to `[Room: name]` silently reduces both tools to the Rooms an Agent created itself — with no error, because a wrong id is an ordinary tool failure the model reads as text. |
| **`GetHelpTool` is constructed from the other tools, and last.** | It reports the catalog, so it takes the list rather than joining it — and it copies that list, because the tool server is handed a fixed set at the same moment. Registering it alongside the others would either loop or need a second, hand-maintained list of tool names. |
| **The Work Dir is not a jail.** | `Bash` and `Write` run agent-side against the real disk, and the adapter auto-loads `CLAUDE.md` and `.claude/settings.json` from that `cwd` — a second, implicit way a persona can arrive. |
| **`PersonaRunner` must not become a `BackgroundService`.** | Hosted services are fixed at build time; these are created per Persona at runtime. `PersonaSupervisor` is the hosted service. |
| **Editing a Persona *or changing its Model, its Effort or its Adapter* restarts its session and loses its conversation memory.** | A system prompt, a Model, an Effort *and* an Adapter are all fixed at `session/new`; none can be swapped into a running session, so "the edit takes effect" can only mean stop-and-restart. `PersonaSupervisor` compares the whole last-started `Persona` by record value equality — text, Model, Effort **and** Adapter — so a save that changes none of them does not trigger a needless restart, and the check cannot go stale the next time `Persona` grows a field. **Adapter proved that claim**: it was added to the record in 2026-09-16's Adapters work and `NeedsRestart` needed no edit at all. |
| **Removing a Persona does not remove its Agent, Rooms or Transcripts — but it does remove its Model and its Effort.** | A deliberate repo-owner decision, and still true of a *removal*. `PersonaStore` still has no reference to `ITeamDirectory`, so it cannot cascade anything itself. The Model and the Effort are different in kind: both are part of the Persona itself, not a chat fact that outlives it. Leaving either row behind would silently resurrect an old Model or Effort if a Persona of the same name were created later. |
| **A *rename* does cascade, and it is not a counter-example to the row above.** | Since 2026-09-15, `PersonaRenameCascade` renames the Agent's Team Directory row in place — keeping its id, so Rooms, memberships and Transcripts follow — and moves the Work Dir. A removal means the Teammate is gone and its Rooms are facts that outlive it; a rename means the Teammate is still here under another Name, which is why one cascades and the other must not. `PersonaStore`'s decoupling survives intact: it raises `PersonaRenamed` and knows nothing about who listens; the cascade is a separate subscriber holding both. See [ADR-0011](../adr/0011-a-rename-moves-the-teammate-not-its-history.md). |
| **`PersonaRenamed` fires before `PersonasChanged`, and `ITeamDirectory.RenameUser` is synchronous — both on purpose.** | `PersonaSupervisor` reacts to `PersonasChanged` by starting a runner under the new Name, whose `hello` mints a **new user id** unless a row already carries that Name. The rename must therefore be committed before that event is raised, and an `Action<T>` handler cannot await — so this one Team Directory write is synchronous, matching `PersonaModelStore`'s precedent. Making it async, or swapping the two event raises, restores the ghost silently: a logged warning and nothing on screen. |
| **The model catalog is read by spawning an adapter, even when `Acp:Enabled` is false.** | That flag exists because ACP *spends money*; the probe spends none, because it never starts a Turn. Gating it would leave the picker empty in the default configuration and defeat the feature. What keeps it honest is *when* it runs — only when a New/Edit form opens, never on a page load. |
| **The effort catalog is probed per model, so changing the Model in the card spawns an adapter.** | This extends the row above one step: still free (no prompt turn, no tokens), still never on a plain page load, but now also on a `<select>` change, and cached per model id. Leaving the model at the agent's default costs nothing extra, because that list comes off the model probe's own session. |
| **No test may reach the real `ModelCatalogProbe`.** | It spawns a `node` process. `TeamWebApplicationFactory` substitutes a `FakeModelCatalog`, and `TeammatesPage_DoesNotProbeForModelsOnAPlainLoad` pins that a plain GET probes zero times. This is the same class of rule as `DemoAgent:Enabled=false`. |
| **Store a Model's id, never its display name.** | `AgentModelOption.Id` is what `session/set_config_option` takes. A display name in `persona_models.model` will never resolve and will log a warning on every single restart, forever. |
| **Store an Effort's id, never its display name.** | Same failure as the row above, for `persona_efforts`: a display name never resolves against `AgentEffortOption.Id` and logs a warning on every restart forever. |
| **The adapter's own `"default"` effort is filtered out of the picker and stored as null.** | The card's blank option is that choice. Null means no `set_config_option` is sent at all, which is a genuinely *different* wire behaviour from sending `"default"` (which explicitly clears the adapter's pin layer) — two options with one label would hide that. |
| **A picker whose catalog is still being probed is `Disabled`, not merely hinted.** | An unread catalog is an *empty* one, so `ModelChoices`/`EffortChoices` render just the blank default plus the synthesised entry for the stored id — a two-item list that looks like the agent's whole answer. Issue #39 measured it: two entries at 265 ms, six at 8.5 s, with no sign the first reading was provisional. `Disabled` and **not** `ReadOnly`: both refuse to open the popover, but MudBlazor 9.10.0 styles only the disabled one (`.mud-input.mud-disabled` dims the text and dots the underline) — there is no read-only rule for an input at all, so a read-only select looks live and silently swallows the click. |
| **A handler that awaits two probes in a row must `StateHasChanged()` between them.** | `ComponentBase` renders a handler at its first yield and at its completion, and nowhere in between — so the Model select used to repaint when the *effort* probe answered, not when its own catalog landed, which is most of the "~11 seconds" issue #39 named. Start the second probe *before* the repaint and await it after (`Task efforts = this.LoadEffortsAsync(); this.StateHasChanged(); await efforts;`): the flag it sets on the way in is what stops the intermediate render asserting "This model offers no effort choice" about a ladder nobody has read. |
| **A Model the agent does not advertise is a warning, never a failure.** | The session starts on the agent's default instead. A stale stored Model must not be able to brick a Persona — `session-config-options.md` is explicit about this, and a test pins it. |
| **A component attribute bound to a `string` parameter must carry a leading `@`.** | `Name="this.cardName"` passes the *literal text* `this.cardName`; only `Name="@this.cardName"` passes the field. **The compiler cannot catch this** — a literal is legal wherever a string is expected, so it builds clean with zero warnings and fails only on screen. Parameters of any other type (enum, bool, list, `EventCallback`) are parsed as C# either way, which is why a usage can be half-broken and look consistent. This shipped once, in `Teammates.razor`; `TeammatesRazorSourceTests` now guards it. |
| **A Budget refusal must be worded as terminal.** | A model that reads "budget spent" as transient retries, spending the very Turn the refusal exists to save — or worse, posts the same thing into another Room, which has a Budget of its own. `ChatService.BudgetRefusal` holds the wording once so both doors into a post carry the same words: `AgentConnection` copies it into a `ProtocolError`, and `PostMessageTool` copies it into the tool result. `get_help` says the same thing in prose. No test can prove a real model obeys it — that is manual checklist step 23. |
| **The Budget counter is read and written inside the per-Room `postLocks` semaphore.** | Deciding whether a post fits is check-then-act. Two concurrent Agent posts that both read `Used` one below the Budget would both conclude they fit, and the Room would take one more Message than it granted — a `ConcurrentDictionary` makes the *operation* atomic, never the *decision*. The same semaphore is also what keeps transcript order equal to event order, so a counter maintained anywhere else could describe no prefix of the Transcript. `ConcurrentAgentPosts_StopExactlyAtTheBudget` fails if this moves. |
| **`ReplyGate` checks the Budget before the Room rule, and that ordering is the rule.** | A Mention does not buy a Turn past the cap. Expressed as two booleans at the call site it would be an unwritten ordering of two `if`s, and reversing them would silently exempt every Mentioned Agent from the cap while still compiling and still passing every test written before the cap. Returning one `ReplyDecision` from inside the gate makes it unreorderable. |
| **The Open action launches a process on the server, ungated, by explicit decision.** | A browser cannot open a local file from an `http://` page. Safe only because the app runs on the user's own machine; if ever hosted for remote users this action must be removed rather than gated. |
| **A Hook's text never contains `mcp__team__`; the prefix is filled in by code.** | Letting a human hand-edit the prompt that names the tools is the way to reintroduce the silent failure the row above describes. `{{toolNames}}`, `{{toolName}}` and `{{helpTool}}` are substituted from the live tool roster, and the prefix is built from the same `ToolServerName` constant handed to `AppToolServer` — one line of executable code in the application names the server. A user can omit the tool list, which `HookValidator` flags; they cannot misspell a tool into nonexistence. Typing the prefix into a default would quietly undo that. |
| **Editing a Hook must never restart a session.** | `PersonaSupervisor.NeedsRestart` compares the `Persona` record, and a Hook is deliberately not part of it. Restarting would make every edit land immediately and throw away that Agent's conversation memory every time someone reworded a sentence. The cost is accepted and paid for elsewhere: a `NextSession` Hook is silently inert on a running Teammate, which is why the settings page badges exactly those fields. See [ADR-0007](../adr/0007-model-facing-text-is-configuration.md). |
| **`HookValidator` reports and never refuses.** | A save that blocks on a finding is one users route around, and the point of Hooks is trying wordings no checker can judge in advance. `Error` means "this will probably not work", never "this is rejected". The two findings that matter — a prompt that stopped naming a tool, a Room label that lost `{{roomId}}` — are both invisible at runtime, so surfacing them is the entire value; refusing on them would be a different and worse feature. |
| **An absent `hooks.json` is normal, and the app must not create one.** | It holds overrides only, so absent means "nothing is overridden" and every key resolves to `HookCatalog`. Writing 22 defaults at startup would turn "I have changed nothing" into a file that must be kept in step with the code forever, and would admit a state where the file and the code disagree about what the app does bare. The file appears on the first save; the settings page says so, because someone who goes looking beforehand finds nothing and reads that as broken. |
| **A `[Parameter]` may not be of an `internal` type.** | Razor generates component classes as `public`, so a parameter typed `internal` fails with `CS0053` — this is why `TeammateCardMode`, `HookTiming`, `HookIssue` and the `Settings` view-model records are public while nearly everything around them is not. Widen the one type the parameter needs, never the whole feature: `HookCatalog`, `IHookSource` and `HookStore` stay internal behind a public view-model built by a static factory. |
| **Health outranks pipe liveness, and the ordering in `PersonaStatusResolver` is the rule.** | `AgentGateway.IsOnline` means only that a pipe connection exists. Any of `PersonaRunner`'s three long-lived loops can die and leave that pipe open, so an Agent can be deaf and still report online - checking connectivity first would show a dead runner as Online for as long as its pipe happens to stay open, silently, while still compiling and still passing every test written before a health signal existed. Four surfaces render this badge; one pure function is what stops them deriving it four different ways. Same argument as `ReplyGate` returning one decision instead of two booleans. |
| **A Turn the Human stopped is not a failure, and a spent Room Budget is not either.** | A Turn ends completed, stopped, timed out or failed, and only the last two are faults. A Stop reports no health state, raises no alert and does not break the consecutive-failure streak; a `budgetExhausted` refusal belongs to ADR-0006's Continue prompt, and a badge there would mark an Agent working exactly as designed. Tell a Stop from a shutdown by the **run token**, never by exception type - both arrive as `OperationCanceledException`, and everywhere else in this codebase that exception means shutdown. See the row below for the third producer of that exception. |
| **A Turn ends four ways, not three, and the fourth must not be mistaken for the second.** | Completed, stopped, **timed out**, failed. `Acp:TurnIdleTimeoutSeconds` bounds how long an Adapter may say *nothing* — silence, not duration, so any event restarts it and a long streaming Turn is never killed. **TRAP 1:** a timeout and a Stop cancel the same linked token and arrive at the same `catch (OperationCanceledException)`, and the clause that catches a Stop reports no health state and does not break the failure streak — so a timed-out Turn caught there would report a hung Adapter as a perfectly healthy Persona. The run token cannot separate them, so each producer writes a **latch** (`MarkStopRequested`, `MarkTimedOut`) **before** the cancellation it causes, and the filter reads the latch, never the exception. A Stop wins a tie, because only a real `StopTurn` can set `StopRequested`. **TRAP 2:** the timeout cancels the **far side first and its own token second** — the opposite order from the Stop path. `DotAcpAgentSession.CancelAsync` no-ops when no prompt is in flight, and `PromptAsync`'s own `finally` clears that flag before the consumer resumes, so cancelling locally first guarantees `session/cancel` is **never sent** and leaves the Adapter working on a Turn nobody will read. The Stop path keeps the opposite order deliberately, trading that for responsiveness on a Human-initiated Stop; a watchdog reporting a failure does not get to make that trade. `PersonaRunnerTests.TurnIdleTimeout_AStopInsideTheWindow_IsStillReportedAsStopped` pins the first trap and `..._ReachesTheAdapterWithASessionCancel` the second. |
| **A Room's silence note describes one delivery, and is never re-derived from scrollback or on load.** | It is what *this* Message meant, held per view, cleared by the next Message and by a Room switch. Re-deriving it would use membership as it is **now**, so a Room that has since gained a Member would have its history re-explained under rules that were not in force at the time - the confusion [product observation 3](product-observations.md) describes, manufactured by the very affordance built to remove it. A reload losing the note is the accepted cost. The one exception is the Continue button: `ExtendBudgetAsync` re-reads the Members and re-parses the Mentions at click time, so saying beforehand what it will do is the same computation, not a re-derivation. See [ADR-0012](../adr/0012-a-room-says-why-it-stayed-quiet.md). |
| **A note that instructs must never fire for a Teammate that cannot answer, and must never predict a reply.** | Two halves of one rule. An unreachable Agent is filtered out of `RoomReplyResolver`'s recipients rather than folded into the decision, because `AgentGateway.DeliverAsync` skips a disconnected Agent too - without the filter, a Mention of an offline Teammate resolves to `Expected` and the Room tells the Human to address someone who cannot reply. And the copy says "name one to ask for a reply", never "no teammate will reply", because the Reply Gate is permission and not obligation: a pipe client may answer anything, so the view knows what a delivery was *labelled* and never what a runner *did*. **Narrowed 2026-09-16 by roadmap item 8.** This row used to justify that from `following` being unknowable to the view. That was true of the wire and false of the process - `RoomFollows` is an in-process singleton, so `Chat.razor` reads it and passes it to the resolver like any other input. The wording rule survives its original reason, which is why it is stated on its own terms now. |
| **The Room's health strip needs a reason, not just an unhealthy state.** | A reason exists exactly when something *reported* a failure; an Agent that is merely not running has none. `Team:Acp:Enabled` is false by default, so in a stock configuration no Persona has ever started and every Agent is Offline - listing those puts a permanent `role="alert"` in every Room, telling the Human nothing the Teammate tile does not already show. An alert that is always on is one nobody reads, which is the failure the strip exists to prevent. |
| **A colour or font literal belongs in `MainLayout.razor.css` and nowhere else.** | Every other stylesheet reads `var(--mud-palette-*)` or `var(--mud-typography-*)`. `ThemeSourceTests` fails the build on a literal in `app.css` or any `.razor.css`, with one written exemption: `#blazor-error-ui` in `MainLayout.razor.css`. That exemption used to be about legibility; since 2026-09-14 it is **load-bearing**. The banner's `color-scheme: light only` no longer protects it — that trick worked because `--text-primary` was a `light-dark()`, and a `--mud-palette-*` variable is a flat value swapped in C# by `IsDarkMode`, which `color-scheme` cannot touch. Literal `black` is now the only thing keeping that banner readable under a dark Theme. See [ADR-0010](../adr/0010-a-theme-is-a-mudblazor-theme.md). |
| **Every `var()` in every stylesheet names a MudBlazor variable, or `--font-mono`.** | Two tests enforce it in both places it can break: `AppCss_UsesOnlyMudBlazorVariables` for `app.css`, and `ScopedCss_UsesOnlyMudBlazorVariables` enumerating `Components/**/*.razor.css`. The second exists because its absence nearly shipped a defect: `ReconnectModal.razor.css` was left referencing nine deleted Tokens, and an unresolved custom property resolves to **nothing**, not to a fallback — so the reconnect modal would have rendered invisible at exactly the moment the circuit drops. Both tests enumerate rather than naming files, so a stylesheet added later is covered the day it appears. |
| **"Do not touch this component" never implies "do not touch its stylesheet".** | The corollary of the row above, and the reason that defect got written in the first place. `ReconnectModal.razor` and its `.razor.js` are genuinely untouchable — its buttons carry no `@onclick` and Blazor's own JS binds them by `id`. Its **stylesheet** is an ordinary tokenised file and must migrate with every other. When something is put out of bounds, say which of its files, and why, for each one. |
| **Every imported palette value carries the VS Code key it came from, as a trailing comment.** | The Themes under `src/Huddle.App/Themes/VsCode/` were converted once by hand and **no importer ships**, so there is no mapping code to read — the comment is the mapping's only record. A bare `Background = "#1f1f1f",` is unreviewable; 340 hex literals all compile, and a wrong one is invisible until someone notices a surface looks slightly off. The comment names the key, flags a fallback taken because the preferred key was absent, and records any alpha that was composited away. Same habit [ADR-0009](../adr/0009-a-theme-is-a-stylesheet-layered-over-the-tokens.md) set for `theme.css`: *the name and the mapping cannot separate*. See [ADR-0016](../adr/0016-vs-codes-bundled-themes-are-converted-once-not-imported.md). |
| **A contrast floor must name what the colour actually paints.** | `ThemeCatalogTests` holds every Theme to six pairs. A seventh was nearly added, holding `LinesDefault` to WCAG 1.4.11's 3:1 "focus ring" minimum — but the focus ring is `--mud-palette-text-primary` (`app.css` says so, under a comment ending *"Do not 'improve' this back to an accent colour"*), and `LinesDefault`'s one consumer is `.teammate-tile:hover`'s border, whose state the same rule also signals by changing the background. The wrong pair failed `huddle` itself at 2.00:1 and was one edit from being "fixed" by adding an eighth documented exception — freezing a false claim about the code into a justification comment. **A guard that is slightly wrong and well-commented is worse than no guard.** |
| **Persisted Room state goes in a sibling table, never a new column on `rooms`.** | The schema is created with `CREATE TABLE IF NOT EXISTS`, so an existing `team.db` **never gains a column and never says so** (see [Traps](traps.md)). `archived_rooms` follows `PersonaModelStore` and `PersonaEffortStore`: its own table, created in the same `InitializeAsync`, where *presence of a row* means archived and absence means the default. `PreExistingDatabase_WithoutArchivedRoomsTable_StillSupportsArchiving` builds a pre-feature database by hand and proves it. The same trap is why Room auto-naming detects a custom name by comparison rather than a `name_is_custom` flag. See [ADR-0017](../adr/0017-a-room-can-be-archived-or-deleted.md). |
| **Archiving a Room is a display filter and must never reach the delivery path.** | An archived Room is still live: Agents post into it, its Transcript grows, its Budget is untouched. Only `RoomList` and `Chat` filter on it. Putting the check anywhere near `ReplyGate` or `AgentGateway.DeliverAsync` would add a sidebar preference to the most load-bearing logic in the app, where the rules about who receives what already are. The accepted cost is that an archived Room can accrue Messages nobody sees until it is unarchived. |
| **Deleting a Room must delete both halves of it, and `room_members` goes first.** | A Room is stored twice — `rooms`/`room_members` in `team.db`, and `{DataDir}/rooms/{roomId}.jsonl` on disk ([ADR-0002](../adr/0002-jsonl-file-per-room.md)). A delete that forgets the file leaves an orphan Transcript. Inside SQLite the order is `room_members` → `archived_rooms` → `rooms`, in one transaction: `PRAGMA foreign_keys=ON` is set per connection and `room_members.room_id REFERENCES rooms(id)` has no `ON DELETE CASCADE`, so the reverse order throws. |
| **A `SELECT` over `rooms` and `ReadRoom` change in lockstep.** | `ReadRoom` reads its columns **positionally**. Four queries now select a fourth column (`a.room_id IS NOT NULL` from the `archived_rooms` LEFT JOIN), and adding a fifth to one query without updating the reader fails at runtime, not at compile time — there is no warning and no analyser for it. |
