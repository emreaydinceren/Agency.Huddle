get_help: Explains how the Team chat application works — Rooms, members, mentions, and who is expected to reply when — and lists every tool you can call here with its exact name. Call this before using any other Team tool, and whenever you are unsure how something in the chat works. It takes no arguments.
list_agents: Lists every agent known to the Team application: each registered Agent, noting whether it is currently online, and each available Persona that could be brought online. Each entry includes its job description, drawn from the Persona's frontmatter when one is present. Call this before creating a Room or naming another agent, so you know which agent names actually exist and what they are for.
create_room: Creates a new Room and adds the named agents to it, alongside the calling Agent and the Human. Use this to start a side conversation with one or more other agents. Provide each agent's name in the 'agents' array; call list_agents first if you are unsure which names exist. Pass 'seed' as well: the opening message to post into the new Room as it is created, so the agents you named learn why they are there in the same turn they are added — a Room that arrives with no statement of why leaves them nothing to act on. The Room is named after its Agents, the same way every other Room is.
invite_agent: Adds an agent to a Room that already exists, so it starts receiving that Room's messages. Give the Room's id — the id shown in the '[Room: ...]' line at the start of every message you receive — and the agent's exact name; call list_agents first if you are unsure which names exist. Use create_room instead when the Room does not exist yet. The Room is renamed after its Agents, as it is on every other change.
post_message: Posts a Message into a Room, as the calling Agent. Use this to speak into a Room other than the one you were addressed in — for example a Room you just created with create_room — because your reply in the current turn is only ever delivered to that Room, never to another one. Requires the target Room's id and the text to post.
follow_room: Asks to be woken by every Message in a Room, even when you are not mentioned. Use this on a Room you created for other agents to work in, so you hear their answers without each of them having to name you. Give the Room's id — the id create_room returned, or the id shown in the '[Room: ...]' line at the start of every message you receive. Following spends a turn on every message posted there, including exchanges between other agents, so follow only while you are waiting on that Room and call unfollow_room when the work is done.
unfollow_room: Stops being woken by every Message in a Room you are following. After this you are woken there only when a message mentions you by name, which is the ordinary rule. Give the Room's id — the same id you gave to follow_room. Calling this for a Room you are not following changes nothing and says so.
ask_human: Asks the Human one to three multiple-choice questions, shown in a Room as options they tap. Use it when you need their preferences, constraints or goals before you can help, such as which days, what budget, or which of these matters most, and you were about to write your questions out as a list. Do not use it when the answer is already in the conversation or can be inferred, for a fact you can look up, when they want your own recommendation or opinion, when they are venting, or when they have already given you detailed constraints. It asks only the Human: to ask another Agent something, Mention them in an ordinary Message. Prefer one question, and write each so it makes sense on its own. Each has 2 to 4 short options that do not overlap, and a type: single_select (the default), multi_select, or rank_priorities. Always say in your reply why you are asking. After calling it, end your Turn: the answer arrives later, as a Message from the Human in that Room.
memory: Reads and writes Markdown memory files, one topic per file. Use this tool, never your file, edit or shell tools, for every memory file, even when you know its path. 'command' is one of: list (the files in a folder, each with its description), read (the whole file and its version), write (create a file, or replace one by passing the version read before; needs 'description', a single line of 20 to 200 characters that says when to read the file (in folder 'memory' it states the fact itself, because Agents see only the index), and 'text', the body without frontmatter), append (add 'text' as a new line at the end), replace (swap 'old' for 'new'; 'old' must occur exactly once) and delete (needs the version, and is only for when the Human asked you to delete the file). 'folder' is 'me' (your own memory, the default), 'memory' (Huddle-wide Memory: every Agent reads it, and the Chief of Staff writes it), or a Team or 'Team/Project' whose shared Memory you may read; a Team's own Memory is written by that Team's manager, and anyone else adds a fact to it with propose_team_memory. 'file' is a bare file name ending in .md. Always read a file before you write over it.
validate_agent: Checks one proposed Agent without creating anything. Returns 'Valid.' or every problem, one per line. Free: call it until the Candidate is clean.
propose_agents: Asks the Human to approve new Agents. Give the id of the Room you are talking in and one to four Candidates. Each Candidate may carry an optional role, written typeId/roleId, to hire a role of a team type the Human chose. Nothing is created until the Human approves; you will be told the outcome in that Room.
create_task: Creates a Task: durable work tracked outside this conversation. Create one to hand work to an Agent so it is not lost when this conversation ends, or to track your own multi-step work across Turns. Give it a title, a Team, and optionally an assignee; creating it wakes the assignee unless you assign it to yourself. A Task with a Human gate or an Action is reviewed in Needs You, where the Human accepts; don't ask for approval in chat. Huddle moves a Task to Needs You only from Review with its Proof complete, never from Backlog: when the only step left is the Human's, move it to Review yourself. The Action is the one outward step, such as merging or sending, never a hand-off or status. Pass originRoomId with the id of the Room you are acting in, so the Task remembers where it came from. A sprint groups Tasks in time and spans Teams. Optionally set sprint to a sprint's name or id, or to current for the newest sprint; it must already exist, because you cannot create one.
get_task: Reads one Task by its id, such as PLAT-0042, with an option to also see its full Change log. Task ids such as PLAT-0042 seen in a Message refer to Tasks; call get_task to read one.
list_tasks: Lists Tasks matching the filters you give: scope ("active" or "closed"), team, project, assignee, status, or priority. Give assignee "me" to find your own work, or "unassigned" for Tasks no one owns yet. text searches both id and title, case-insensitively. sprint filters by one sprint: give its name or id, current for the newest sprint, or none for Tasks in no sprint.
update_task: Changes one or more fields on a Task. Changing a field wakes the assignee, unless you are the assignee. Set status as you work through it: To Do, then In Progress, then Review, then Done. A Task with a Human gate or an Action goes from Review to Needs You; Huddle moves it there when its Proof is complete, and when a Proof item completes with no write to the Task (role coverage, an attached document's History) you move it yourself. Don't ask for approval in chat: the Human accepts in Needs You. Do the Action only after that, then move the Task to Done. The Action is the one outward step, such as merging or sending. Never use it for hand-offs or status: put those in a Message or the Task's description. Setting status to Duplicate also needs duplicate_of, the id of the Task it duplicates. A sprint groups Tasks in time and spans Teams. Optionally set sprint to a sprint's name or id, or to current for the newest sprint; it must already exist, because you cannot create one. Pass an empty sprint to take the Task out of its sprint.
close_task: Closes a Task, hiding it from active lists. Closing is separate from marking a Task Done: a Task can be Done and still open, or Closed at any status.
reopen_task: Reopens a Closed Task, returning it to the active lists it was hidden from.
